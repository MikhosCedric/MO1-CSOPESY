## 3. CLI Command Specifications & UI Updates

### 3.1 `process-smi` (Memory Summary View)
Generates a high-level GPU/CPU-like status overview:
* Displays `CPU-Util` (percentage of active CPU cores).
* Displays `Memory Usage` (Used MiB / Total MiB) and `Memory Util` percentage.
* Lists all currently running processes alongside their allocated memory footprint (e.g., `process05 134MiB`).

### 3.2 `vmstat` (Detailed Virtual Memory Statistics)
Displays fine-grained system and memory statistics formatted as follows:
* `total memory`: Total main memory in bytes.
* `used memory`: Total active memory used by processes.
* `active memory` / `inactive memory` / `free memory`: Physical memory breakdowns.
* `idle cpu ticks`: Number of ticks wherein CPU cores remained idle.
* `active cpu ticks`: Number of ticks wherein CPU cores are actually executing instructions.
* `total cpu ticks`: Number of ticks that passed for all CPU cores.
* `pages paged in`: Accumulated number of pages paged in.
* `pages paged out`: Accumulated number of pages paged out.

### 3.3 `screen -s <process_name> <process_memory_size>`
* Creates a new process with a given name and memory allocation.
* **Validation:** All memory ranges are [2^6, 2^16] bytes and the power of 2 format. The console will throw an "invalid memory allocation" message to the user if it's outside of range.

### 3.4 `screen -c <process_name> <process_memory_size> "<instructions>"`
* Sends a string of 1 to 50 instructions to be executed by the specified process.
* Instructions are semicolon-separated.
* Throws "invalid command" if the instruction size is not met.

### 3.5 `screen -r <process_name>` (Updated Terminal Attach Logic)
* Access the screen anytime. If the process name is not found/finished execution, the console prints "Process <process name> not found."
* **Access Violation State:** If the process name has prematurely shut down due to a memory access violation error, the console should print "Process <process name> shut down due to memory access violation error that occurred at <HH:MM:SS>. <Hex memory address> invalid."

## 4. Memory Manager & Demand Paging Architecture

### 4.1 Page & Frame System
1. **Virtual Paging:** The total number of frames is equal to `max-overall-mem` / `mem-per-frame`. Let P be the number of pages required by a process and M is the rolled value. P can be computed as M / `mem-per-frame`.
2. **Demand Paging:** Pages are loaded into physical memory frames on demand. When a process references a virtual memory page that is not currently in a frame, a page fault occurs, and the required page is brought from the backing store into a free frame.

### 4.2 Backing Store (`csopesy-backing-store.txt`)
* The backing store is represented as a text file that can be accessed at any given time. It is saved in a text file "csopesy-backing-store.txt."
* If no frames are free, a page replacement algorithm selects a page to be evicted to the backing store.

## 5. Instruction Set & Process Execution Mechanics

### 5.1 Symbol Table Segment
* `uint16` variables are stored in the symbol table segment of the process.
* The symbol table segment has a fixed size of 64 bytes. Your program can store a maximum of 32 variables.
* If the limit is reached, succeeding instructions involving variable declarations will be ignored.
* `uint16` variables are clamped between (0, max(uint16)) and consume 2 bytes of memory.

### 5.2 Emulated Instruction Details
* `DECLARE <var> <value>`: Declares a uint16 variable.
* `ADD <varA> <varA> <varB>`: Adds variables.
* `WRITE <memory_address> <value>`: writes uint16 value to the specified memory address.
* `READ <var> <memory_address>`: performs a retrieval of a uint16 value from memory and stores it to a variable, var. If the memory block isn't initialized, the uint16 value is 0.
* `PRINT` operations for outputting values.
